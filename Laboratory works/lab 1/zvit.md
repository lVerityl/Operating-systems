__Завдання попередньої підготовки__

1. Словник базових англійських термінів:

- Virtual Machine (Віртуальна машина) - Програмне середовище, яке імітує роботу окремого комп'ютера.
- Hypervisor (Гіпервізор) - Програмне забезпечення для створення та керування віртуальними машинами.
- Virtualization (Віртуалізація) - Технологія створення віртуального апаратного або програмного середовища.
- Host OS (Хостова операційна система) - Операційна система фізичного комп'ютера, на якому працює віртуальна машина.
- Guest OS (Гостьова операційна система) - Операційна система, встановлена всередині віртуальної машини.
- Kernel (Ядро) - Центральна частина операційної системи, яка керує апаратними та програмними ресурсами.
- Distribution (Дистрибутив) - Набір ядра Linux, системних інструментів та прикладного програмного забезпечення. 
- Open Source (Відкритий код) - Програмне забезпечення, вихідний код якого доступний для перегляду та модифікації.
- Command Line Interface (CLI) (Інтерфейс командного рядка) - Текстовий спосіб взаємодії з операційною системою за допомогою команд.
- Graphical User Interface (GUI) (Графічний інтерфейс користувача) - Інтерфейс, у якому керування системою здійснюється за допомогою графічних елементів.
- Host (Хост) - Фізичний комп'ютер, на якому працює віртуальна машина.
- Guest (Гість) - Віртуальна операційна система або система, що працює всередині віртуальної машини.

2. Поняття «гіпервізор» та його типи

2.1. __Охарактеризуйте поняття «гіпервізор». Які бувають їх типи?__  
Гіпервізор — це програмне забезпечення або програмний компонент, який забезпечує створення та керування віртуальними машинами. Він дозволяє запускати декілька операційних систем на одному фізичному комп'ютері та розподіляти між ними апаратні ресурси.  
__Типи гіпервізорів__:
1. Гіпервізор типу 1 (Type 1) — працює безпосередньо на апаратному забезпеченні комп'ютера та не потребує звичайної хостової операційної системи. Такі гіпервізори часто використовуються на серверах та в центрах обробки даних.(VMware ESXi, Microsoft Hyper-V,(Open-source: Xen, KVM, Proxmox Ve))
2. Гіпервізор типу 2 (Type 2) — працює поверх хостової операційної системи та використовує її ресурси для створення і запуску віртуальних машин.(VMware Workstation, Oracle VirtualBox, Parallels Desktop, QEMU)

2.2. __Компоненти та можливості гіпервізора KVM__:  
2.2.1. Основні компоненти  
   2.2.1.1. Модульт ядра KVM  
   - `kvm.ko` — базовий модуль, що перетворює Linux-ядро на гіпервізор;  
   - `kvm-intel.ko` або `kvm-amd.ko` — модулі, специфічні для апаратної віртуалізації Intel VT-x або AMD-V;  
   - Надає доступ до апаратних можливостей віртуалізації процесора.

2.2.1.2. __QEMU__ (Quick Emulator):  
   - Працює в парі з KVM, забезпечуючи емуляцію периферійних пристроїв (мережеві карти, диски, відеокарти тощо);
   - KVM відповідає за виконання коду процесора на "залізі", а QEMU — за емуляцію решти обладнання;
   - Разом утворюють зв'язку QEMU/KVM.  

2.2.1.3. __libvirt__:  
   - Універсальний API та набір інструментів для управління віртуалізацією;  
   - Абстрагує роботу з KVM, Xen та іншими гіпервізорами через єдиний інтерфейс;  
   - Включає демон `libvirtd`.  

2.2.1.4. __Інструменти управління__:  
  -  `virsh` — консольна утиліта для керування ВМ-Bare Metal ("голе залізо");  
  -  `virt-manager` — графічний інтерфейс;  
  -  `virt-install` — створення нових ВМ.

2.3. __Основні можливості__:
  - Апаратна віртуалізація — використовує Intel VT-x/AMD-V для майже нативної продуктивності;
  - Паравіртуалізовані драйвери virtio — прискорені драйвери для мережі, дисків, що значно підвищують продуктивність порівняно з повною емуляцією;
  - Живе перенесення (live migration) — переміщення працюючої ВМ між фізичними хостами без зупинки;
  - Снапшоти — збереження стану ВМ у певний момент часу;
  - Динамічний розподіл ресурсів — гнучке виділення CPU, пам'яті, дискового простору;
  - Підтримка різних типів сховищ — LVM, NFS, iSCSI, Ceph, локальні файли (qcow2, raw);
  - Мережеві можливості — bridge, NAT, VLAN, SR-IOV для прямого доступу до мережевих карт;
  - Overcommit ресурсів — можливість виділяти більше віртуальних ресурсів, ніж фізично доступно;
  - Безпека — інтеграція з SELinux/AppArmor через sVirt.

__Хід роботи:__  

2. Дайте відповіді на наступні питання:

   2.1. __Перерахуйте етапи для розгортання операційної системи на базі віртуальної машини VirtualBox__:
    - Встановлення VirtualBox на хост-машину (завантаження дистрибутиву з офіційного сайту, встановлення разом з Extension Pack за потреби);  
    - Створення нової віртуальної машини: вибір типу та версії гостьової ОС, задання назви;  
    - Налаштування обсягу оперативної пам'яті (RAM), яка буде виділена ВМ;  
    - Створення віртуального жорсткого диска (VDI, VMDK, VHD);  
    - Налаштування параметрів ВМ (кіл-ть CPU, налаштування відеопам'яті, налаштування мережевого адаптера, налаштування портів USB);  
    - Підключення образу ОС (ISO-файлу) до віртуального оптичного приводу;  
    - Запуск віртуальної машини та завантаження з підключеного ISO-образу;  
    - Проходження процесу встановлення ОС (розбиття диска на розділи, вибір мови, часового поясу, облікового запису користувача тощо);  
    - Встановлення Guest Additions — додаткового пакету драйверів VirtualBox для покращення інтеграції (спільний буфер обміну, автоматичне масштабування екрана, спільні папки);  
    - Перезавантаження та фінальне налаштування встановленої гостьової ОС.
  
   2.2. __Чи є якісь апаратні обмеження при встановленні 32- та 64-бітних ОС?__:  
   - Підтримка процесором: для встановлення 64-бітної ОС процесор хост-машини повинен підтримувати технологію 64-бітних обчислень (Intel 64/AMD64);  
   - Апаратна віртуалізація: для 64-бітних гостьових ОС у VirtualBox зазвичай обов'язково потрібна увімкнена в BIOS/UEFI підтримка Intel VT-x або AMD-V — без неї VirtualBox може не дозволити вибрати 64-бітну гостьову систем;  
   - Обсяг оперативної пам'яті: 32-бітні ОС здатні адресувати максимум ~4 ГБ RAM (фактично менше, зазвичай близько 3,2–3,5 ГБ через резервування адресного простору), тоді як 64-бітні системи можуть використовувати значно більше;  
   - Розмір віртуального диска й продуктивність: 32-бітні системи мають обмеження і на розмір адресованого дискового простору для деяких операцій;
   - Драйвери та сумісність: не всі сучасні драйвери випускаються під 32-бітні системи;  
   - Тип гіпервізора: у деяких старих версіях VirtualBox 64-бітні гостьові ОС взагалі недоступні, якщо в налаштуваннях BIOS хоста вимкнена апаратна віртуалізація.
  
   2.3. __Які основні етапи при встановленні OS Linux в текстовому режимі?__:  
   - Завантаження з інсталяційного носія (ISO/USB) у текстовому (CLI/ncurses) режимі інсталятора;  
   - Вибір мови встановлення та розкладки клавіатури;  
   - Налаштування мережі (якщо потрібно — для завантаження пакетів з репозиторію);  
   - Налаштування часового поясу;  
   - Розмітка дискового простору (вибір диска, створення розділів (root `/`, `swap`, `/home`, `/boot` за потреби), вибір файлової системи (ext4, xfs тощо));  
   - Вибір набору пакетів/профілю встановлення (мінімальний, сервер, базова система тощо — без графічного середовища);  
   - Встановлення базових пакетів системи та копіювання файлів;  
   - Налаштування пароля root та створення звичайного користувача;  
   - Встановлення завантажувача (bootloader), зазвичай GRUB, у MBR або на розділ EFI;  
   - Завершення встановлення та перезавантаження системи;  
   - Первинна конфігурація після першого завантаження (оновлення пакетів `apt update && apt upgrade` / `yum update`, налаштування мережі, часу тощо).
  
   2.4. __Яким чином можна до установити графічні оболонки Gnome та KDE в Linux, якщо вона вже встановлена в текстовому режимі (вкажіть необхідні команди та пакети)?__

Для GNOME:  
```   
sudo apt update
sudo apt install gnome-shell gnome-session gnome-terminal gdm3 -y
або повний набір:
sudo apt install ubuntu-desktop -y
```

Для KDE Plasma:  
```
sudo apt update
sudo apt install kde-plasma-desktop -y
або повний набір:
sudo apt install kde-full -y
```
Ключові пакети, які встановлюються:  
- X11/Wayland сервер (`xorg-x11-server-Xorg` або`xserver-xorg`) — графічна підсистема, без якої DE не запуститься;  
- Display manager — GDM (GNOME), SDDM (KDE), LightDM (універсальний);  
- Мережеві шрифти та бібліотеки (як залежності, встановлюються автоматично);  

Після встановлення потрібне перезавантаження системи (`sudo reboot`), після чого система завантажиться в графічному режимі.

2.5. __Дайте коротку характеристику графічних інтерфейсів, що використовуються в різних дистрибутивах Linux(GNOME та JWM)__

| Критерій | GNOME | JWM |
| -------- | ----- | --- |
| Тип | Повноцінне DE | Легкий WM |
| Споживання ресурсів | Високе | Дуже низьке |
| Функціональність | Багата, "все включено" | Мінімальна, потребує доповнень |
| Цільова аудиторія |  Звичайні користувачі	| Технічні користувачі, слабке "залізо" | 
| Налаштування | Через GUI (Settings, Extensions) | Через XML-конфіг вручну | 
| Типове застосування | Настільні ПК, ноутбуки | Live-системи, старе обладнання, вбудовані рішення |

3. Відповіді на контрольні запитання:  

   3.1. Порівняйте гіпервізори типу 1 та типу 2, яка між ними відмінність та сфера їх застосування?
   | Критерій | Тип 1 (Bare-metal) | Тип 2 (Hosted) |
   | -------- | ------------------ | -------------- |
   | Розташування | Встановлюється безпосередньо на апаратне забезпечення | Встановлюється як програма поверх хостової ОС |
   | Доступ до "заліза" | Прямий | Опосередкований, через хостову ОС |
   | Продуктивність | Висока, мінімальні накладні витрати | Нижча через додатковий прошарок ОС |
   | Надійність/ізоляція | Висока — збій хостової ОС не впливає | Залежить від стабільності хостової ОС |
   | Складність встановлення | Вища, потребує окремого сервера | Проста інсталяція як звичайного застосунку |
   | Приклади | VMware ESXi, Microsoft Hyper-V (роль сервера), Xen, KVM | VMware Workstation/Fusion, VirtualBox, Parallels Desktop |

   Сфера застосування:  
   - Тип 1 — сервери, дата-центри, хмарні платформи (AWS, Azure, Google Cloud), корпоративна віртуалізація, де критична продуктивність та надійність  
   - Тип 2 — персональні комп'ютери розробників, тестування ПЗ, навчання, запуск другорядної ОС паралельно з основною (наприклад, Windows на Mac)  

   3.2. Розкрийте поняття «GNU GPL», яка його основна концепція?  
      - GNU GPL (General Public License) — це ліцензія вільного програмного забезпечення, розроблена Річардом Столменом та Фондом вільного програмного забезпечення (FSF) у рамках проєкту GNU.  
      -  **Основна концепція** базується на принципі "copyleft" (протилежність copyright у сенсі обмежень):  
          - Свобода використання — програму можна запускати з будь-якою метою;  
          - Свобода вивчення та модифікації — доступ до вихідного коду обов'язковий;  
          - Свобода поширення копій;  
          - Свобода поширення модифікованих версій.  
       
   3.3. В чому суть програмного забезпечення з відкритим кодом?

   Основна суть прогрманого забезпечення з вылкритим кодо - це поширення, вивчення, модифікація і вільний доступ до перегляду коду.

__Висновки__:

У ході виконання лабораторної роботи було розглянуто основні принципи віртуалізації та особливості встановлення і налаштування операційної системи Linux.

Було з'ясовано, що гіпервізори поділяються на два типи: тип 1 (bare-metal), який працює безпосередньо на апаратному забезпеченні (VMware ESXi, Hyper-V, Xen, KVM) і застосовується переважно на серверах та в центрах обробки даних, та тип 2 (hosted), що працює поверх хостової ОС (VirtualBox, VMware Workstation) і використовується для навчання, тестування та розробки. Окремо розглянуто гіпервізор KVM, його компоненти (модулі ядра, QEMU, libvirt, virsh) та можливості, зокрема живу міграцію, снапшоти та паравіртуалізовані драйвери virtio.

На практиці було опановано етапи розгортання ОС у віртуальній машині VirtualBox: створення ВМ, налаштування ресурсів, підключення ISO-образу, встановлення системи та Guest Additions. Також з'ясовано апаратні обмеження для 32- та 64-бітних систем, зокрема необхідність підтримки Intel VT-x/AMD-V для 64-бітних гостьових ОС та обмеження 32-бітних систем щодо обсягу оперативної пам'яті.

Було розглянуто встановлення Linux у текстовому режимі та способи довстановлення графічних оболонок за допомогою пакетних менеджерів (apt, dnf), а також переключення між текстовим (multi-user.target, рівень 3) та графічним (graphical.target, рівень 5) режимами завантаження. Порівняння графічних інтерфейсів GNOME та JWM показало, що GNOME є повноцінним сучасним середовищем робочого столу з багатим функціоналом, але вищим споживанням ресурсів, тоді як JWM — легковісний віконний менеджер, придатний для слабкого обладнання та мінімалістичних систем.
